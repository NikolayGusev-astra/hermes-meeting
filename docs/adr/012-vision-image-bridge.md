# ADR-012: Vision-мост для фото-постов (`describe_image`)

**Status:** accepted
**Date:** 2026-08-22
**Deciders:** Николай (user), Rin (agent)
**Related:** [011-tg-post-media](adr/011-tg-post-media.md)

---

## Context

ADR-011 тянет медиа конкретного TG-поста, но фото честно отклонялись
(«транскрибировать нечего»). При этом в хозяйстве уже есть локальный
vision-стек (см. статью «Vision в API за копейки»): LFM2.5-VL в LM Studio для
описания фото/интерфейсов и OvisOCR2 на llama.cpp (:8017) для документов.
Правило роутинга: «картинка = текст в графике → OCR; важна компоновка/фото →
VL». Нативное зрение в контексте агента не нужно — результат переводится в
текст, который кэшируется и переиспользуется.

## Decision

1. **Новый модуль `vision.py`**: `describe_image(path, mode) -> str`.
   - `mode="vl"` (дефолт): POST base64-картинки в `MEETING_LLM_BASE_URL`
     (LM Studio), модель `MEETING_VISION_MODEL` (дефолт `lfm2.5-vl-3b`);
   - `mode="ocr"`: `MEETING_OCR_BASE_URL` (дефолт `http://127.0.0.1:8017/v1`),
     промпт извлечения Markdown из статьи;
   - режим по умолчанию — env `MEETING_VISION_MODE`; автоклассификация
     «OCR vs VL» вне scope v1;
   - только urllib, без новых зависимостей; ошибки бэкенда → `MeetingError`
     с подсказкой «запущен ли LM Studio».

2. **Фото-посты в ADR-011**: `msg.photo` (без видео/документа/войса) →
   скачивание `<channel>_<id>.jpg` + подпись поста рядом
   (`.caption.txt`). Смешанный пост: видео побеждает.

3. **Файловая ветка pipeline**: `.jpg/.jpeg/.png/.webp` → `describe_image`
   → транскрипт «подпись + описание» (`.transcript.txt`, `meta.vision=true`)
   → дальше существующие протокол/саммари без изменений.

## Consequences

+ Фото-пост обрабатывается той же командой, что и видео: одна точка входа.
+ Всё локально, цена ноль, данные не покидают машину.
− Качество описания = качество локальной 2.6–3B VL (текст с картинки читает,
  мелкие детали теряет); при необходимости режим `ocr` или облачная модель
  подключаются env-ом без изменения кода.
− Бэкенд должен быть запущен (LM Studio / llama-server) — ошибка падает
  рано и с понятным сообщением.

## Verification

Офлайн: `test_vision.py` (payload, режимы, HTTP/URLError), 
`test_tg_photo_source.py` (скачивание jpg, caption, видео-победа, роутинг).
Живо: PNG с текстом → LFM2.5-VL вернул текст и структуру кадра.
